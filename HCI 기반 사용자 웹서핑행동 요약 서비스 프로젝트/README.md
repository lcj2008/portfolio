# JustInNeed

JustInNeed는 웹서핑 중 사용자가 어느 문단에 오래 머물고 어디를 다시 읽었는지 기록해, 관심을 보인 내용을 줄글과 마인드맵으로 정리하는 서비스입니다. 여러 페이지를 읽은 뒤 “그 설명이 어느 글에 있었지?”라는 생각이 들면, 요약에 연결된 출처를 따라 원문으로 돌아갈 수 있습니다.

## 한 번의 웹서핑이 요약으로 저장되는 과정

1. **읽기 기록 수집.** 사용자가 Chrome 확장 프로그램에서 세션을 시작하면 확장이 본문을 나누고 문단별 체류 시간, 스크롤, 커서 움직임을 기록합니다. 수집한 로그는 브라우저에 보관했다가 기본 30초 단위로 Spring 서버에 전송합니다.
2. **세션 단위 분석 요청.** Spring 서버는 도착한 로그 조각을 DB에 저장합니다. 사용자가 세션을 종료하면 같은 세션의 기록을 모아 내부 AI 서버에 분석을 요청합니다.
3. **관심 문단 선별.** AI 서버는 문단 길이를 고려한 체류 시간, 재방문, 스크롤 속도 등을 바탕으로 읽기 상태를 추정합니다. K-means로 분류한 네 상태(`Idle`, `Scanning`, `Reading`, `Deep Reading`) 중 뒤의 두 상태에 해당하는 문단을 점수순으로 정렬합니다. 과거 기록이 충분하면 개인 모델을, 기록이 적으면 공통 모델을 사용합니다.
4. **요약 생성과 조회.** AI 서버는 의미가 겹치는 문단을 합치고 선별한 내용을 줄글로 요약합니다. 마인드맵은 비슷한 문단을 주제별로 묶은 뒤 LLM이 키워드와 상하 관계를 제안하고, 코드가 누락된 문단과 잘못된 연결을 검사하는 방식으로 만듭니다. Spring 서버가 결과를 저장하면 사용자는 웹에서 요약·마인드맵과 원문 출처를 함께 확인할 수 있습니다.

세션이 쌓이면 읽기 상태의 분포, 자주 방문한 사이트 분야, 집중해서 읽은 시간대를 살펴볼 수 있습니다. 여러 세션의 주제를 하나의 마인드맵에서 다시 탐색할 수도 있습니다. 읽기 상태는 행동 신호로 추정한 값이며, 관심 문단 선별이 사용자의 실제 평가와 얼마나 일치하는지는 후속 검증 과제입니다.

## 백엔드 역할과 시스템 구성

저는 **Spring Boot 백엔드 개발 전반**을 담당했습니다. 회원이 웹 계정에 확장 프로그램을 연결할 수 있도록 인증을 처리하고, 확장에서 보낸 읽기 기록을 세션별로 PostgreSQL에 저장했습니다. 세션 종료 시 같은 세션의 기록을 모아 내부 AI 서버에 분석을 요청하고, 반환된 요약·마인드맵을 저장해 웹에서 조회할 수 있도록 API를 개발했습니다.

| 구성 요소 | 기술 | 맡은 처리 |
|---|---|---|
| Chrome 확장 프로그램 | JavaScript, Readability | 본문 추출, 읽기 행동 수집, 로그 전송 |
| 백엔드·저장소 | Spring Boot, Supabase, PostgreSQL | 계정 연결, 세션 로그 저장, 분석 요청, 결과 저장·조회 |
| AI 서버 | Python, FastAPI, pandas, NumPy, OpenAI API | 행동 지표 계산, 읽기 상태 추정, 관심 문단 선별, 요약·마인드맵 생성 |
| 웹 프런트엔드 | Next.js, TypeScript | 세션 목록, 요약·마인드맵, 원문 출처와 읽기 통계 표시 |

확장 프로그램과 웹은 Spring 서버를 통해 분석 결과를 주고받습니다. Spring 서버와 AI 서버는 AWS EC2 한 대에서 별도의 Docker 컨테이너로 실행되며, AI 서버는 내부에서만 호출합니다. 발표 대본에 따르면 GitHub Actions가 이미지를 빌드해 Docker Hub에 올리고 EC2가 이를 받아 실행합니다. 웹은 Vercel에 배포했습니다.

## 팀이 해결한 문제

**사이트마다 다른 문단 길이.** 기사 전체를 하나의 HTML 문단에 담은 페이지도 있고, 한 줄씩 문단을 나눈 블로그도 있습니다. 이 상태에서는 같은 10초의 체류 시간이라도 읽은 분량이 크게 달라집니다. 팀은 일반 본문을 문장 경계에 맞춰 약 200자 단위로 나누고, 각 구간의 앞 160자에서 식별자(`pid`)를 계산했습니다. 같은 텍스트를 다시 방문했을 때 이전 읽기 기록과 연결하기 위한 처리입니다.

**전송 도중 끊기는 읽기 기록.** 세션 종료 시점에 로그를 모아 보내는 방식은 브라우저가 중간에 닫히면 기록을 잃을 위험이 있습니다. 팀은 수집과 전송을 분리했습니다. 확장은 전송할 로그와 진행 상태를 로컬에 함께 저장하고, 전송에 실패한 조각은 보관했다가 같은 세션 안에서 순서대로 다시 보냅니다.
